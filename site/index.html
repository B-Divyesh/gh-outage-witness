How it works

Collect and review the evidence

The bundle keeps observations separate from its cautious evidence label.

  1. 1

    Choose one run

    Pass its repository and positive Actions run ID to the CLI.

  2. 2

    Collect available evidence

    The CLI requests run details, jobs, attempts, logs, and current public status.

  3. 3

    Review the redacted bundle

    Check every file and the recorded uncertainty before sharing the ZIP.

Install

Install and capture an incident

Install the GitHub CLI extension. Then pass a repository and run ID.

Install gh extension install B-Divyesh/gh-outage-witness
Capture gh outage-witness OWNER/REPO RUN_ID

Add --runner-log journal.txt only when you want to include a local runner file.

Limits and privacy

Know what the bundle cannot prove

An evidence label is not a verdict. A status incident can support a platform label, but it cannot prove provider fault.

Redaction still needs review. Known credential formats and configured matches are removed. An unusual secret in prose can remain.

Missing sources stay visible. The bundle records unavailable logs or status instead of guessing what happened.
